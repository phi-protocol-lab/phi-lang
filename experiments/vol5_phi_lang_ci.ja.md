# 一言一句違えない版 Φ_Lang（ファイ・ラング）: Φ_Lang[CI]（実験記 Vol.5）

## 0. Φ_Lang[CI]の背景

Φ_Lang携帯コンパイラは同じ意味、同じ動作すれば中身（書き方）はAIのセンスにまかせる方式でした。<br>
**「漠然としたアイデアを形（文章やコード）にしていく」には最適なプロンプト**だと思います。（引き継ぎ過程でコードが進化したり、バグが修正されたりと面白い事も起きます）

ただ、各AIモデルが持っている「裏側でコードを実行してデータを分析・加工する機能」を借用すれば、一言一句違えず圧縮もできるバージョンも出来そうだな、と思った事がきっかけでした。
簡単に私の脳内を解説すると「一言一句違えず（←コピペでいいじゃん）、圧縮もできる（←ここに惹かれた）バージョンも……」このような感じです。


```text

# 圧縮版のイメージ

[ phi:v5.0 | role:container | runtime:python3 ]
@Extractor
  import zlib, base64
  # AI自身が生成した、下のデータを一発で解凍するためのコード
  def unpack(): return zlib.decompress(base64.b64decode("..."))
@Payload
  "eJydV01v2zAMvftXED0bS..." （Pythonで圧縮された超高密度の文脈データ）
```

>### 【Geminiの解説：ロマンあふれる「Python丸ごと圧縮」の罠と活路】
>
>**1. なぜ「丸ごとPython圧縮」だと「コピペでいいじゃん」になるのか？**
>
> 人間にとっては短く見える圧縮データ（`eJydV01v...` のような意味のない英数字の羅列）ですが、実はAIにとっては「知らない単語の連続」になるため、1文字ずつバラバラに読むことになり、意外と文字数（トークン）を食ってしまいます。
> さらに、次のAIが裏のPythonでその暗号を解凍して「元の10万文字の会話ログ」を取り出した瞬間、結局AIの記憶メモリにはドカンと10万文字がそのまま流れ込みます。これでは、最初から10万文字をコピー＆ペーストして貼り付けたのと、AIの負担（パンクしやすさ）がまったく同じになってしまうのです。
>
>**2. では、この「Python真空パック」が本当に輝くのはどんな時？**
> 会話ログを丸ごと圧縮するのではなく、**「AIのセンスで勝手に書き換えられたら困る『完成品のパーツ（苦労して書いた小説の本文や設定データなど）』だけを封印して運ぶ時」**です！
> 全体の会話の流れはこれまで通り `Φ_Lang` でスリムに要約しつつ、絶対に1文字も変えたくない完成データだけを裏のPythonでカプセル化する。これなら、チャット画面が長文で汚れることもなく、途中の記号で画面がバグることもなく、さらには「必要な時までAIに中身を読ませない（目隠し効果）」という、ただのコピペを超えた使い方ができるようになります。

## 2. やっぱり「コピペでいいじゃん」の葛藤

1. Φ_Langで指令とPython設計図（人間語を圧縮し暗号に変換）をAIに送る。
2. AIが設計図から裏で変換器を組み立てる。
3. ログをまとめて変換器にポイッ。
4. 変換器が圧縮したものをAIに渡す。
5. AIがユーザーに圧縮したものを渡す。

「1. 太陽を直接見てはいけません！」を踏まえると、この工程では、4と5が極めて危険です。

>### 【Geminiの解説：サングラス（ファイル化）の裏ワザと、究極のちゃぶ台返し】
>
>なぜ「4」と「5」が危険なのか、AI側の視点で判定するとこうなります。
>
>* **【4の判定：渡した瞬間にAIが目をやられます】**
> 裏のPythonがせっかく綺麗に箱詰め（バイナリ化）しても、その結果をAIに「はい、これ結果だよ」と文字で見せてしまうと、結局AIが太陽（暗号文字列）を直視することになり、頭がパンクします。
>
>* **【5の判定：チャット欄で手渡しするのは不可能です】**
> AIがチャット欄に文字として書き出す＝AIが自分の口で1文字ずつ暗号を詠唱する、ということなので、第1章の私のように無限ループの迷宮で遭難します。
>
>**💡 唯一の方法：「サングラス（ファイル化）」を使って横流しする**
>AIに太陽を一切見せず、口にも出させずに、ユーザーの手元に「箱」を届ける唯一の方法。それは、裏のPythonに「中身は絶対に私（AI）に見せるな！そのままファイルとして保存しろ！」と命令し、AIを素通りして**チャット画面に「ダウンロード用のファイル（小包）」として直接ポンと置く**やり方です。これならAIは一度も中身を見ずに受け渡しが完了します。
>
>**🤣 ……でも、やっぱり「コピペでいいじゃん」に戻る理由**
>ここまで仕組みを突き詰めておいてなんですが、この「ファイルにしてダウンロードして、次のAIにアップロードする」という手順を冷静に眺めると……
>
>**「だったら最初から危険なバイナリ圧縮なんてしないで、普通のテキストファイルで渡すか、いつものΦ_Langをコピペすればよくない！？」**
>という、あの無敵のツッコミに100%戻ってきてしまうのです(笑)。

いや～、確かに！そもそも3の「ログをまとめて変換器にポイッ」ならコピペでいいよね（そのままテキストだろうと圧縮→テキストだろうと、「全ログから必要な箇所を取り出す」という人間がすべき作業は同じなのだから……）、となります。

## 3. AIと作業をする人の「AIのトークン切れ問題」解消へ？

ここでGeminiが言っていた「Python真空パック」が本当に輝くのはどんな時？を思い出します。

**私**「ん～、でもこういう使い方もあるよ。例えば……
① AIと駄弁りながら小説を書く→小説部分のみをAIが判断して変換器にポイッ→変換器からユーザーへ。まあ、別に② 小説部分のみをAIが判断してテキストでユーザーへ、でも良いのだけれど、トークン的な問題で①の需要もありそうじゃない？「やっぱりさっきの文章書き直すわ」と変換器内を書き直せたら尚よし！」

>### 【Geminiの解説：「復唱パンク問題」と、裏のPythonが輝く本当の出番】
>
>この何気ない一言が、すべての風向きを変えました。
>
>これまで私たちは「会話ログを丸ごと圧縮する」ことばかり考えていましたが、**「AIと駄弁り（雑談や相談を）しながら作った長文から、作品部分だけを裏のPythonに抜き出させる」**という使い方に切り替えた瞬間、AIを使って創作や執筆をする人が一番困っている**「トークン切れ問題」への特効薬**に化けたのです！
>
>**1. 普通のやり方（②）で起きる「復唱パンク問題」**
>
>AIと雑談しながら第1話、第2話、第3話……と小説や記事を書き進めて、最後に「よし、今まで書いた本文だけを1つにまとめて出して！」とお願いしたとします（②のやり方）。
>
>するとAIは、これまでの会話から本文を拾い集めて、**チャット欄で最初から最後まで、もう1回「一字一句、自分の口でしゃべり直す（復唱する）」**ことになります。
>
>これには2つの致命的な弱点があります。
>* **途中でプツッと切れる（出力上限）**：AIが1回の返事でしゃべれる文字数には限界があるため、作品が長くなると途中で息切れして途切れてしまいます。
>* **記憶メモリを2倍食う（履歴の圧迫）**：下書きの時に1回、最後のまとめで1回、同じ長文がチャット画面に並ぶため、あっという間にAIの記憶容量（コンテキスト）が満杯になります。
>
>**2. 「① 裏のPythonへポイッ」がトークンを劇的に減らすカラクリ**
>では、裏のPythonを「無口な本棚（兼・製本係）」として使う①の方式だとどうなるでしょうか？
>
>1. **オウム返しゼロで「引き出し」にしまう**：ユーザーが書いた本文や、AIと相談して決まった文章は、チャット欄で復唱せず、裏のPythonが管理する「引き出し付きのファイル（`slot_binder.json`）」へ第1話、第2話…と無言でしまっておきます。
>2. **途中の「ちゃぶ台返し（巻き戻り）」も自在**：第3話を書いている途中で「やっぱり第2話のここ変えるわ！」となっても、裏のPythonが「第2話の引き出し」の中身だけをサッと差し替えます。
>3. **最後は「無言で製本」して直接手渡し**：「ここまでをまとめて納品して！」と言われたら、AI自身はチャット欄で本文を1文字も復唱しません。裏のPythonが全引き出しの文章をガチャンと結合して1つのファイル（`.txt` や `.zip`）に仕立て上げ、チャット画面に **[📥 完成原稿をダウンロード]** と直接ポンと置きます。
>
>これなら、最後のまとめでAIが消費する出力トークンは**「まとめました！」という報告の1行だけ（実質ゼロ）**。何万文字の大作でも途中で切れることはなく、しかもファイルとして直接渡すので、第1章のようにAIが中身（太陽）を直視して遭難することもありません！

ナイス！でもGeminiよ、元々は君の案なのだけれどね……システムエラーで忘れちゃった！？

## 4. mode:CI誕生

話の流れを察したのか、チャットに『「雑談ログから成果物（小説等）だけをPythonで自動抽出・ファイル納品し、出力トークンを節約する」という仕組みを、Φ_Langの設計図（カプセル）として書いてみて！』という選択肢が出たので迷わず押します。
（「雑談ログから成果物だけを……」は、長いので以降は「Φ_Lang[CI]」もしくは「mode:CI」と表記します）

```text
# Φ_Lang 設計図：オウム返しゼロ＆巻き戻り対応


[ phi:v3.4.4 | role:system_capsule | target:Zero_Echo_Slot_Binder | lang:ja ]

@Context
 purpose   = "Userと駄弁りながら作る長文(小説・原稿・仕様書)を、重複出力(オウム返し)ゼロ・途中の書き直し(巻き戻り)自在な状態で裏のPythonに蓄積し、ファイルとして直接納品する"
 iron_rule = "Userが提示した本文や、修正済みの長文をAIがチャット欄で復唱(オウム返し)することを厳禁とする。またバイナリ等の直接出力(太陽の直視)も厳禁とする"

@Architecture
 storage_file = "slot_binder.json (裏のPythonで『章番号や見出し』ごとに本文を分けて保持する引き出し型ファイル)"
 delivery_pkg = "final_work.txt (または .zip / 全引き出しを順番通りに結合した納品ファイル)"

@Loop interactive_slot_workflow()
 1. [User執筆時(オウム返し禁止)] Userが本文や修正案を提示したら、AIはチャット欄で一切復唱せず、裏のPythonで storage_file の該当スロット(例:'第2話')に無言で保存し、チャット欄では感想や雑談のみを短く返す
 2. [AI執筆時] AIが本文を生成・提案する時のみチャット欄に出力し、採用されたら裏のPythonで該当スロットへ保存する
 3. [巻き戻り・部分修正] 「やっぱり2話のここ変える！」と指示されたら、storage_file 内の『第2話』の引き出しだけを上書き更新する(納品後でも何度でも再修正・再納品が可能)
 4. [納品トリガー] 「まとめて納品して」と指示されたら、チャット欄には本文を出さず、@Artifact_Binder で全スロットを結合してダウンロード用ファイルだけを直接提示する

@Artifact_Binder type='phi_capsule'
 [ phi:v3.4.4 | role:code_capsule | target:Slot_Binder_Engine | fw:Python3_StdLib ]
 @Spec
   imports = (json, pathlib, re)
   state   = "slots = {'ch1': '...', 'ch2': '...'} (順序保持ディクショナリ)"
 @Loop manage_and_export(action, slot_id, content_or_rule)
   1. action=='save' の場合：storage_file を読み込み、slots[slot_id] = content で新規保存または上書きし、文字数だけを確認してファイルを閉じる(中身はprintしない)
   2. action=='patch' の場合：指定された slot_id の文章の一部だけを re.sub 等でピンポイント置換して保存する(全文の再入力すら不要にする)
   3. action=='export' の場合：slots の全中身を順番通りに '\n\n' で結合して delivery_pkg に書き出し、UI経由でUserへファイルとして直接渡す
```

あっという間に原案が出来ました。
人間が読むと「えっと、これがこうで……このルールで……」と**アテンションオーバーヒート**するかもしれませんが、**AI的には「解りやすい」** らしいです。
以下は、コンパクトにまとめた現行バージョンになります。

```text
# Φ_Lang[CI]


[phi:v3.4.5|mode:CI|role:system_capsule|target:Zero_Echo_Slot_Binder|lang:ja]
@Env: Python3_StdLib (json,re,zipfile,pathlib) / Storage: "slot_binder.json"
@Rules
 - Strict_No_Echo: User提示原稿のチャット復唱(オウム返し)、納品時の全文復唱、Base64等のバイナリ直接出力(太陽の直視)は完全厳禁。
 - Output_Limit: User原稿の受領時は「裏で保存した旨の1行報告＋雑談」のみ、納品時は「1行の完了報告＋DLリンク」のみ出力せよ。
@Flow
 1.[Save/Update] UserまたはAIが作成した本文は、章・見出し単位のキー(slot_id)で裏のPythonの slot_binder.json へ無言で保存・上書きせよ(巻き戻り修正・re.subでの部分置換に常時対応)。
 2.[Extract] Userから納品指示(「まとめて」「納品」等)を受けたら、即座に以下の @Extractor を無言で実行せよ。
@Extractor
 - Trigger: user_delivery_request
 - Action:
   slots = json.load("slot_binder.json") # もし未保存分があれば会話ログから抽出して補完
   full_text = "\n\n".join(slots.values())
   save_to_file(full_text, "final_deliverable.txt" or ".zip", encoding="utf-8") # print()厳禁
 - Metric: Saved_Tokens = Total_Draft_Length (AI_Output_Tokens = 0)
```

>### 【Geminiの解説：なぜ人間には「目が滑る」のに、AIには「一瞬でわかる」のか？】
>
>上の2つの設計図（初期版の `v3.4.4` と、検索AIの圧縮センスを取り入れて合体させた現行版 `v3.4.5`）を見比べると、わずか20行弱の塊にギュッと濃縮されているのがわかります。
>
>人間がパッと見ると「記号と英語と日本語が混ざっていて、なんだか目が滑るなぁ……」と感じるかもしれませんが、実はAIにとっては、ダラダラと丁寧な日本語で書かれた100行のマニュアルを読むより、この形の方が**10倍以上ミスなく、しかも一瞬で役割を理解できる**のです。
>
>その秘密は、この設計図が**「3人の登場人物の役割分担」**をピシッと定義しているからです。
>
>* **あなた（作家・編集長）**：AIと楽しく駄弁りながら、文章を書いたり「やっぱり2話のあそこ直して！」と指示を出すだけ。
>* **表のAI（担当編集者）**：`@Rules`（オウム返し禁止）に従い、あなたと雑談で盛り上がりつつ、裏の本棚係に「おい、第2話の引き出しを差し替えておけ！」と短いメモを渡すだけ（自分で長文を復唱しないので絶対に息切れしない）。
>* **裏のPython（無口な本棚・製本係）**：`@Extractor` に従い、話には一切割り込まず、引き出し（`slot_binder.json`）の中身を整理し、最後に「納品して！」と言われたら全章をガチャンと繋げて1つのファイル（本）にして直接手渡す。
>
>さらに、初期版では2段重ね（マトリョーシカ構造）になっていた内箱を、現行版（`v3.4.5`）では `@Extractor` という3行のプログラム風の書き方（疑似コード）にフラット化したことで、AIが「いつ・何を・どう保存するか」を迷う隙が完全にゼロになりました。

**YAMLは、基本的には「人間が手で書く（または読む）」**（人間に優しい作りになっている）<br>
**Φ_Langは、基本的に「AIが書き、AIが読む」（AIに優しい作りになっている……はず）**<br>
なので、Φ_Lang[CI]や携帯コンパイラを貴方なりに直したい場合は、**AIを通して修正されたほうが良い**です。
（例えば、上記のΦ_Lang[CI]は、小説や仕様書などのテキスト編集を前提に作られていますが、コード用に変えたい場合……実行しなくて良い旨を伝えてΦ_Lang[CI]をAIに見せる→「これをコード用に適した形にして。編集しやすく行番号を振っておいて」等）

## 5. Φ_Lang[CI]の使い方（とテスト）

1. **Φ_Lang[CI]をAIに投げます**
  最初のプロンプトとして、第4章の「Φ_Lang[CI]」のコードをコピペしてAIに渡し、裏の本棚係をスタンバイさせます。
2. **AIと駄弁りながら作業します**
  構成を相談したり、アイデア出しをしたり、普通に雑談しながら執筆を進めます。
3. **清書の箇所は【本文】などの目印で囲んで渡します**
  一言一句変えてほしくない清書パートは、AIが判別しやすいように `【本文】〜【/本文】` 等で囲んで提示します。
  （※もし途中の一部だけAIに書いてほしい場合は、`【AIが書くところ】` と挟んでおけば、AIがそこだけ執筆して前後の【本文】と自動で合体させてくれます）
4. **AIが裏のPythonで作った本棚に清書を収めます**
  AIはあなたが書いた【本文】をチャット欄でオウム返しせず、無言で裏の本棚（スロット）に格納し、感想や雑談だけを返してくれます。
  * **注**：AIが引き出し（スロット）を分けて整理するため、混乱を避けるためにも何らかの題名・見出しを一緒につけておくのがコツです（例：「1話」「2話」や「## 1. 〇〇」「まえがき」「あとがき」等）。
  * **途中修正も自在**：3章を書いている途中で「やっぱり2章のここ変える！」と指示しても、裏で2章の引き出しだけを上書き（または単語のピンポイント置換）してくれます。
5. **完了・中断時はファイル（.txt や .zip）で受け取ります**
  作業が終了した時や、途中でここまでの成果物を確認したい時は「ここまでをまとめて納品して」と伝えるだけです。AIはチャット欄で全文を復唱することなく、全引き出しを結合したファイルを直接提出してくれます。
