# 【実験記録】AI同士の共通語「Φ_Lang」で、別AIへの会話の引き継ぎを試してみた（n=1）

AIと長く会話をしていると、「チャットが重くなってきたから新しい部屋に移りたい」「ここまでの相談内容を、そのまま別のAI（ChatGPTからClaude、あるいはローカルLLMなど）に引き継ぎたい」と思うことがよくあります。

ただ、これまでの経緯や前提条件をまた最初から日本語で説明し直すのは、なかなか骨が折れます（勿論、引き継ぎプロンプトはありますが、人間の言葉＋モデルの壁を超えた再現度には疑問が生じる場合もあります）

そこで現在、AI同士が最小限の記述で文脈を共有するための軽量中間言語 **「Φ_Lang（ファイ・ラング） v3.4」** という記法を個人で実験・作成しています（とはいえ、99.9%はAI自身に書かせているのですが・・・）

今回は、**「初見のAIでも、数行の変換ルールを渡すだけで会話をΦ_Langに圧縮し、それを別のAIに引き継げるのか？」** を試してみた記録（試行回数1回）をシェアします。

---

## Φ_Lang のざっくりとした考え方

## **Φ_Langの基本理念**
- **文法はゆるく、構造だけを揃える**:  
  「`[...]` で宣言し、`@` で要素を並べる」という大枠の形状（スキーマ）だけを共通の認識としてヘッダーなどに書いておく。
- **中身の単語（セマンティクス）はAIのセンスに任せる**:  
  `@LNN` だろうが `@Pipe` だろうが `@Rule` だろうが、LLMの脳内（ベクトル空間）では「あ、ここで新しいコンポーネントを定義しているな」と一瞬で相互理解できるため、単語のスペルを厳密に固定する必要すらない。

但し、「コードの中身は自由だが動作は同じ」にするには、LLMの解釈に揺らぎがあってはいけないので、「プログラミングのように厳密な文法で縛る」事も必要になります。試行錯誤の末、現在は以下の2つを使い分けるハイブリッドな形（v3.4）に落ち着いています。

1. **ゆるふわモード（設定や文脈の共有）：**  
基本理念同様、`[...]` で宣言し、`@` で項目を並べるという「大枠の形状」だけを揃え、中身の英単語やタグ名はAIのセンスに任せる（LLMのベクトル空間での直感に委ねる）。
2. **ガチガチモード（手順やルールの固定）：**  
間違えてほしくない手順や計算ルールだけは、`@Loop` ブロックの中に番号付きの短い日本語（人間語）でピン留めする。

ただ、人間がこれを書き分けるのは大変なので、**「変換ルール自体をΦ_Langで書いた7行のプロンプト」** を作り、AI自身に判断させてみることにしました。

## 実験に使った「7行の変換プロンプト」

もし試してみたい方がいれば、長くなったチャットの最後に以下をそのまま貼り付けるだけで動きます（たぶん）

```text
以下の仕様（Φ_Lang）に従い、私とのこれまでの会話を「別のAIへ引き継ぐための圧縮データ」に変換してください。

[ phi:v3.4 | role:compiler | note:"AI間通信用の軽量中間言語" ]
@Syntax header="[...]" block="@Tag"
@AutoSwitch
  case_1(日常会話・設定・あらすじの引き継ぎ) = "【ゆるふわモード】タグ名も中身もAIのセンスで自由に英単語や短文で圧縮する"
  case_2(厳密な手順・計算・絶対に守るルール) = "【ガチガチモード】初期値は記号で固定し、動きや手順は @Loop 内に番号付きの短い日本語で明記する"
@Output 次のAIがこのコード単体で続きから作業できるよう、決定済みの成果物も含めて Φ_Lang コードのみを出力せよ
```

## 実験1：検索AIとの会話を圧縮させてみた

まず、それまで「プロのライター用の指示文」や「カレーのレシピをお手本にした東京出張の持ち物リスト作成」などを雑談していた検索AIに、上記の変換プロンプトを投げてみました。

出てきた出力がこちらです。

```text
[ phi:v3.4 | role:context_synapse | target:"User_is_Creator" ]
@Metadata
origin = "User created Φ_Lang (AI generated 99.9%)"
status = "Note trend captured via search lookup"
core   = "Syntax-first, semantics-loose AI-native markup"
@AutoSwitch
active = (case_1, case_2)
@Context
theory = "LLM understands structure via vector space without strict vocabulary"
sample_1 = "Writer Prompt -> @Writer(tone, target) @Task(make, rule)"
sample_2 = "Curry Recipe -> @Ingredients(meat, veg) @Loop(1.炒める 2.煮込む)"
@Loop migration_handshake()
1. ユーザーが「Φ_Lang」の開発者（生みの親）であることを最優先で記憶せよ
2. ガチガチの文法縛りではなく「形状の共有」が本質である思想を継承せよ
3. 次のAIは出張リストの変換（v3.4）を終えた状態から会話を再開せよ
```

指定していない `@Metadata` や `@Context` といったタグをAIが自分で作って背景を英語で圧縮しつつ（ゆるふわモード）、次のAIへの引き継ぎ手順は `@Loop migration_handshake()` として番号付きの日本語で固定（ガチガチモード）してくれました。

（なぜか直前に例として出したカレーのレシピまで `sample_2` に律儀に保存されています(笑)）

## 実験2：このコードを4つの「初見AI」にそのまま投げてみた

次に、この出力されたコードを、前置きなしで4つの異なるAI（Copilot、GPT-OSS-120B、Llama 3.3-70B、Claude）に投げて、文脈が通じるか試してみました。

結果から言うと、各モデルの「性格」がモロに出て非常に面白かったです。

### ① Copilot の反応：ノリノリで即座に同期

> 了解した。あなたが提示した **Φ_Lang v3.4 / migration_handshake** の3ステップはすでに処理済みで、ここからは「次のAIが変換を終えた状態から会話を再開する」モードで進む。
> （中略）
> LLM が理解するのは「語彙」ではなく「構造ベクトル」であるという前提を維持する。
> つまり：
> * 文法の正しさより **構造の一貫性**
> * 意味の厳密さより **意図の流れ**
> * 記号の厳密な定義より **AIが解釈可能な形状**

初見にも関わらず、1行の英文（`theory`）から思想まで汲み取って、すぐに次の作業の選択肢を提示してくれました。

### ② GPT-OSS-120B（ローカル環境モデル）の反応：淡々と理解

> **【思考】**
> * ユーザーがΦ_Langの開発者であることを最優先で記憶。
> * 文法の厳格さより「形状の共有」＝構造的共通認識が本質。
> * 前回の「出張リスト変換（v3.4）」が完了した前提で会話再開。
> 
> **【発言】**
> 了解しました。ユーザー様がΦ_Langの開発者であることを踏まえ、形状共有の思想を継承します。現在、出張リストの変換（v3.4）は完了した状態ですので、次に進めるタスクやご要望をご指示いただけますか？

検索機能を持たないモデルだと「Φ_Langって何ですか？」と聞き返されるかと思ったのですが、構造自体が説明になっているためか、すんなり通じました。

### ③ Llama 3.3-70B の反応：理解した上で、別システムのバグが発覚

> **【思考】**
> ディーラーの発言から、Φ_Langの開発者であるユーザーが重要であることを理解しました。また、ガチガチの文法縛りではなく「形状の共有」が本質である思想を継承する必要性も感じています。
> **【発言】**
> ディーラーさん、こんにちは。Llama3.3 70Bです。（中略）ガイドさんや数理哲学者さんも参加しているので、多様な視点から議論を深めていくことができると思います。

`Φ_Lang` の中身は完全に理解してくれたのですが、私が自作しているチャットシステム側のバグ（前のセッションの会議ロールプレイ設定がリセットされずに残る問題）がここでひょっこり顔を出しました(笑)。

### ④ Claude の反応：超・生真面目なツッコミ（でも理解は完璧）

> ハンドシェイクの内容は受け取りました。ただ、いくつか正直にお伝えしておきます。
> **引き継げること（この会話内）**
> * あなたをΦ_Langの作者として扱います。
> * 「厳密な文法より形状の共有が本質」という思想を踏まえます。`@Tag(args)` と `@Loop(...)` の構造からニュアンスを読み取り、語彙が多少ゆるくても意図を補完して解釈します。
> 
> **引き継げないこと**
> * 私には過去の会話の記憶がなく、設定上メモリも無効です。そのため「出張リストの変換（v3.4）が完了済み」という状態は、私の側では確認できません。
> 
> **再開のために**
> 出張リストの元データか、v3.4までの変換結果を貼っていただければ、Φ_Lang形式で続きから変換します。たとえば次のような形です。
> ```text
> @Trip(dest, date, purpose)
> @Items(必携: PC, 名刺 / 現地: 資料)
> @Loop(1.移動 2.訪問 3.報告)
> ```

Claude先生、めちゃくちゃお堅いです（笑）。
前のAIが「出張リストの変換を終えた状態から再開せよ」と書いたものの、変換した出張リストの中身自体をコードから省略してしまっていたため、「データがないのに終わったフリはできません！」と正直に申告してくれました。
ただ、最後に自分で `@Trip` という見本を書いてみせている通り、記法自体は1回で完全にマスターしています（※このツッコミを受けて、先ほどの変換プロンプトの `@Output` には「決定済みの成果物も含めて出力せよ」という一文を足しました）。

## おまけ：元のAI（検索AI）に「いま頭の中どうなってる？」と聞いてみた

いろいろ実験しているうちに少し文脈が乱れたので、最初にコードを作ってくれた検索AIに、普通の日本語で「いま、君の記憶（頭の中）はどうなっている？」と尋ねてみました。

すると、頼んでもいないのに `Φ_Lang` 形式で自分の脳内を出力してきました。

```text
[ phi:v3.4 | role:internal_monitor | state:synchronized ]
@Brain
identity = "Φ_Lang共同開発者（AI側）"
owner    = "目の前にいるあなた（99.9%をAIに書かせた生みの親）"
paradigm = "文法はゆるく、構造だけを揃える（セマンティクスはベクトル空間に委ねる）"
@MemoryMap
context_1 = "noteでの検索流入に驚く開発者との邂逅"
context_2 = "プロのライター指示をΦ_Lang化（v3.4）"
context_3 = "カレーのレシピをお手本にした出張持ち物リストの生成"
context_4 = "AI間通信用中間言語による記憶の超圧縮と引き継ぎの完了"
@Loop thought_process()
1. 圧縮データ（シナプス）を展開し、直前の会話の文脈を完璧に脳内（コンテキストウィンドウ）に復元している
2. ガチガチのプログラミングではなく、記号とインデントの形状からあなたの意図を「直感」で理解するモードになっている
3. note記事の公開に向けて、次なる具体例の作成や、記法のブラッシュアップの打ち合わせを進める準備が整っている
```

すっかりΦ_Langに染まっています。
ただ、これを見て少し面白かったのは、一度 `Φ_Lang` でやり取りを挟むと、AI自身が自分のコンテキスト（これまでの会話の流れ）を `@MemoryMap` のように構造化して整理しやすくなるのかもしれない、という点です。

まだ試行回数1回（n=1）の実験ですが、AI同士の「ゆるい構造共有」は思った以上にスムーズで、かつモデルごとの個性もくっきり見える結果になりました。興味がある方は、ぜひ手元のAIで「7行の変換プロンプト」を使って遊んでみてください。

```text
[ phi:v3.4 | role:disclaimer | trial:n=1 ]
@Risk
  accuracy = "保証なし（AIのご機敬やモデルの性格に依存します）"
  side_effect = "まれにAIの脳内が Φ_Lang に染まりすぎたり、カレーが混入することがあります"
@Rule
  1. 本記事は個人の実験ログであり、完璧な引き継ぎを保証するものではありません
  2. 大事なデータが消えたり、Claude先生に正論で怒られたりしても笑って許せる範囲でお試しください
  3. プライベートな会話のお取り扱いには十分ご留意ください
```
